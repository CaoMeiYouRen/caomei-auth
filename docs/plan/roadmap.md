# 项目路线图 (Roadmap)

本文档概述草梅 Auth 的中长期发展方向与大颗粒度阶段规划。候选条目、优先级与验收要点见 [backlog.md](./backlog.md)；当前阶段原子条目见 [todo.md](./todo.md)；准入与归档规则见 [规划规范](../standards/planning.md)。

> **当前状态**：**阶段 2「安全收口与迁移预备」进行中**（2026-11-05 用户授权）。
> 阶段范围与验收口径见 [阶段 2 登记记录](../design/governance/2026-11-05-phase2-registration.md)；本阶段只做安全 / 质量收口与两条迁移的预备，不替换页面、不全量翻译。

---

## 阶段 1: 稳定性、规范化与核心增强（主体完成，已暂停）

_目标：通过重构和技术规范升级，打造稳健、安全的统一认证基石。_

- [x] **架构解耦 (G1)**: 邮件、短信、验证码模块完成解耦与 DI 引入。
- [x] **文件瘦身 (G2)**: 超长文件清理，逻辑下沉至 Composables。
- [x] **Zod 基础设施**: 引入 Zod 实现 Schema 驱动校验，前后端共用 Schema。

> 阶段 1 的已完成部分见 [已完成工作归档](../archive/completed-work.md)。剩余候选（i18n 全量落地、测试覆盖率达标）已迁入 backlog / 阶段 2，不在本阶段保留未完成条目。

---

## 阶段 2: 安全收口与迁移预备（当前阶段）

_目标：在进入两条大迁移前，清掉安全与质量硬债，并完成组件库与 i18n 的低风险预备。_

- **M1 安全与合规收口**：CodeQL #20 复核（2026-11-30 前）、SSO 历史配置排查、安全台账复核。
- **M2 Zod 后端迁移收尾**：剩余 8 个 handlers + 测试 + 文档收口。
- **M3 测试覆盖率第一阶段**：复测基线，阶段目标 max(30%, 复测基线 + 10pp)；定向补测 `server/api` / `composables` / `components/base`。
- **M4 caomei-ui 迁移预备**：用量快照 + 白名单初值 + 版本锁定 + 回退方案 + 接入基座（P0/P1），双库并存，**不替换页面**。
- **M5 i18n 迁移预备**：`@nuxtjs/i18n@10` 技术验证 + Zod per-parse error map 验证，**不全量翻译**。

> 原子条目与状态见 [todo.md](./todo.md)；范围、验收、依赖与风险见 [阶段 2 登记记录](../design/governance/2026-11-05-phase2-registration.md)。

---

## 后续方向（未授权）

以下方向不属于当前阶段，作为中长期方向保留；候选详情与触发条件见 [backlog.md](./backlog.md)。未授权方向不构成启动授权。

### 开发者生态与集成优化

- 轻量化 Web / Node.js SDK。
- 文档中心自动化、API Playground。
- 插件 / 钩子系统。
- 飞书、企业微信、钉钉等国内办公场景社交登录。

> 候选详情见 [backlog §2.7](./backlog.md#27-开发者生态长期方向)。

### 安全增强与智能化管理

- 风险管控体系（地理位置 / 设备指纹）。
- 安全告警系统（异地登录、高频失败、异常 IP）。
- 高级审计日志（CSV / JSON 导出，SOC2 / ISO27001）。

> 候选详情见 [backlog §2.8](./backlog.md#28-安全增强长期方向)。

### 企业级特性与 SaaS

- 多租户 SaaS。
- 组织 / 部门管理、权限委派。
- LDAP / AD 集成。

> 候选详情见 [backlog §2.9](./backlog.md#29-企业级特性长期方向)。

---

## 跨阶段候选方向（未授权）

- **组件库迁移到 caomei-ui（正式迁移）**：本阶段只做 P0/P1 预备；P2+ 页面替换待本阶段结论与用户授权。见 [backlog §2.1](./backlog.md#21-组件库迁移到-caomei-ui)。
- **i18n 全量落地**：本阶段只做 M1 技术验证；M2+ 页面 / 邮件 / API 全量翻译待本阶段结论与用户授权。见 [backlog §1.2](./backlog.md#12-i18n-全量落地)。
- **体验与性能**：时区设置、注册控制、Admin 日志高级筛选、性能审计、Demo 数据增强。见 [backlog §2.2–§2.6](./backlog.md#2-功能性需求feature-backlog)。
