# 项目路线图 (Roadmap)

本文档概述草梅 Auth 的中长期发展方向与大颗粒度阶段规划。候选条目、优先级与验收要点见 [backlog.md](./backlog.md)；当前阶段原子条目见 [todo.md](./todo.md)；准入与归档规则见 [规划规范](../standards/planning.md)。

> **当前状态**：无进行中阶段（2026-11-05 起暂停）。原阶段 1 未完成项已迁入 backlog，等待下一阶段范围评估与用户明确授权后再登记。未授权方向不构成启动授权。

---

## 阶段 1: 稳定性、规范化与核心增强（主体完成，未收尾）

_目标：通过重构和技术规范升级，打造稳健、安全的统一认证基石。_

- [x] **架构解耦 (G1)**: 邮件、短信、验证码模块完成解耦与 DI 引入。
- [x] **文件瘦身 (G2)**: 超长文件清理，逻辑下沉至 Composables。
- [x] **Zod 基础设施**: 引入 Zod 实现 Schema 驱动校验，前后端共用 Schema。

> 阶段 1 的已完成部分见 [已完成工作归档](../archive/completed-work.md)。剩余候选（i18n 全量落地、测试覆盖率达标）已迁入 backlog，不在本阶段保留未完成条目，等待重新授权。

---

## 阶段 2: 开发者生态与集成优化

_目标：提升集成便利性，让开发者更快接入。以下为方向，未授权启动。_

方向包括轻量化 Web / Node.js SDK、文档中心自动化、插件 / 钩子系统与国内办公场景社交登录。候选详情与验收要点见 [backlog §2.7](./backlog.md#27-阶段-2--开发者生态)，本路线图不重复登记条目。

---

## 阶段 3: 安全增强与智能化管理

_目标：通过高级安全审计与智能分析提升平台防御能力。以下为方向，未授权启动。_

方向包括风险管控体系、安全告警系统与高级审计日志。候选详情见 [backlog §2.8](./backlog.md#28-阶段-3--安全增强)。

---

## 阶段 4: 企业级特性与 SaaS

_目标：面向大型组织和云原生环境提供多租户支持。以下为方向，未授权启动。_

方向包括多租户 SaaS、组织 / 部门管理与 LDAP / AD 集成。候选详情见 [backlog §2.9](./backlog.md#29-阶段-4--企业级特性)。

---

## 跨阶段候选方向

以下方向不属于现有阶段，作为跨阶段候选登记在 backlog，是否进入阶段由用户决策：

- **组件库迁移到 caomei-ui**（[backlog §2.1](./backlog.md#21-组件库迁移到-caomei-ui)）：以 caomei-ui 替换 PrimeVue 4 生态，统一设计 token 与组件行为。
- **i18n 全量落地**（[backlog §1.2](./backlog.md#12-i18n-全量落地)）：覆盖 Web、邮件、API 与错误消息。
- **安全与质量收口**（[backlog §0 组合 A](./backlog.md#0-候选阶段组合建议未授权)）：SSO 历史配置排查、CodeQL 告警复核、Zod 剩余 handlers、测试覆盖率。
