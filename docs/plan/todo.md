### M1 登录事件基座（P0 🛠️🛡️）

- **目标**：建立登录事件的唯一数据源与写入契约，为查询、统计与热力图提供稳定输入。
- **优先级**：P0（M2 / M3 全部依赖事件数据；无事件源则只能继续用 `Session` 近似）。
- **范围**：`LoginEvent` 实体与索引、better-auth 生命周期写入插件、通道 / 结果枚举、保留期与惰性清理、事件写入失败降级、Demo 模式。
- **验收标准**：成功 / 失败登录、2FA 挑战与验证、登出、社交 / SSO 回调结果均落库；事件写入异常只 warn 不阻断认证；不记录密码、验证码、令牌、备份码 / 恢复码；保留期可配置且清理可测；SQLite / MySQL / PostgreSQL 建表脚本同步。
- **不做什么**：不把文件审计迁库；不做事件导出；不做风险评分；不改认证流程。
- **依赖**：阶段 9 `logger.audit` 口径、阶段 11 挑战插件钩子。
- **交付物**：实体 + 插件 + env + 建表脚本 + 单测；4–5 次提交。
- **风险与缓解**：写入放大延迟 → 失败只 warn、单条 insert、索引受控；隐私 → 仅管理员可见、保留期、无导出；Demo 数据 → 确定性生成。

#### M1.1 事件模型与索引

- **目标**：新增 `LoginEvent` 实体（`type` / `result` / `channel` / `userId` / `ip` / `userAgent` / `metadata` / `createdAt`）与查询索引。
- **验收标准**：枚举固定为登记口径；`userId` 可空（匿名 / 未知用户失败）；索引覆盖 `createdAt`、`(type, createdAt)`、`(userId, createdAt)`、`(result, createdAt)`；`server/database/index.ts` 与 `database/sqlite/create.sql` 同步；仓储 helper 提供写入 / 查询 / 清理入口；实体与枚举单测。
- **交付物**：`server/entities/login-event.ts`、`server/utils/login-events/repository.ts`、建表脚本、单测。
- **依赖**：无。

#### M1.2 写入点接线

- **目标**：通过 better-auth 生命周期钩子写入事件，覆盖成功 / 失败登录、2FA 挑战与验证、登出、社交 / SSO 回调结果。
- **验收标准**：每条路径有成功 / 失败用例；事件写入抛错时认证继续并写 `logger.warn`；不包含敏感字段；2FA 挑战事件复用阶段 11 的通道标识；社交 / SSO 记录 provider 与结果；Demo 模式生成确定性事件。
- **交付物**：`server/utils/login-events/plugin.ts`、`lib/auth.ts` 注册、单测 / 集成测试。
- **依赖**：M1.1；阶段 11 `two-factor-coverage` 插件钩子。

#### M1.3 保留期与清理

- **目标**：`LOGIN_EVENT_RETENTION_DAYS`（默认 90，范围 1–3650）与清理入口；管理端统计查询按进程内 1 小时节流惰性清理。
- **验收标准**：缺省 / 非法 / 越界回落；清理只删过期事件；节流在进程内生效；手动脚本支持 dry-run 与显式确认；不引入常驻调度器；单测覆盖边界。
- **交付物**：env 解析、`pruneLoginEvents`、`scripts/maintenance/prune-login-events.mjs`、单测。
- **依赖**：M1.1。

#### M1.4 事件契约与枚举矩阵

- **目标**：用一份契约测试锁住事件类型 / 通道 / 结果枚举与写入路径的对应关系，防止新增通道漏记。
- **验收标准**：矩阵覆盖 7 类事件 × 10 类通道的适用组合；未知通道回落 `unknown`；结果只允许 `success` / `failure`；新增枚举时测试与类型同批更新；Demo 模式不写真实用户。
- **交付物**：`tests/unit/server/login-events-contract.spec.ts`、类型导出。
- **依赖**：M1.2。

### M2 Admin 事件查询（P1 🛠️）

- **目标**：在管理端提供可筛选的事件查询与统计，补齐现有会话视图看不到的失败 / 挑战事件。
- **优先级**：P1（M1 的事件数据需要有消费面；也是热力图的数据基础）。
- **范围**：`GET /api/admin/login-events`（筛选 / 分页）、`GET /api/admin/login-events/stats`（总量 / 类型 / 结果 / 独立用户与 IP）、`/admin/logs` 新事件视图、5 语文案与组件测试。
- **验收标准**：管理员可组合筛选事件类型 / 结果 / 用户 / IP / 时间；分页与排序稳定；非管理员 403；统计与查询口径一致；Demo 模式可用；空 / 加载 / 错误态完整。
- **不做什么**：不做导出；不做实时推送；不改现有会话视图筛选语义。
- **依赖**：M1。
- **交付物**：2 个 API + 事件面板 + 单测；3–4 次提交。
- **风险与缓解**：大时间窗查询慢 → 索引 + 默认 30 天；信息过载 → 事件与会话分区展示。

#### M2.1 查询 API

- **目标**：`GET /api/admin/login-events` 支持类型 / 结果 / 通道 / 用户 / IP / 时间 / 分页 / 排序。
- **验收标准**：Zod 查询 schema 与前端共享；索引命中；非法参数 400；非管理员 403；Demo 数据遵循同一筛选；返回脱敏字段（不含 metadata 中的敏感值）。
- **交付物**：端点、共享 schema、单测。
- **依赖**：M1.1。

#### M2.2 统计 API

- **目标**：`GET /api/admin/login-events/stats` 返回总量、按类型 / 结果计数、独立用户数与独立 IP 数、每日趋势。
- **验收标准**：与查询筛选共用同一条件构造器；空数据返回零值；Demo 模式确定性；非管理员 403；统计查询触发惰性清理但受 1 小时节流。
- **交付物**：端点、共享 schema、单测。
- **依赖**：M2.1、M1.3。

#### M2.3 事件视图

- **目标**：在 `/admin/logs` 增加事件视图（Tab 或并列区块），包含筛选、表格、分页与用户链接。
- **验收标准**：事件类型 / 结果 / 通道 / IP / 时间筛选可用；表格列含时间、类型、结果、通道、用户、IP、UA（截断）；空 / 加载 / 错误态；5 语文案键齐全；组件测试覆盖筛选与空态。
- **交付物**：`components/admin/logs/login-events-panel.vue`、`composables/admin/use-login-events.ts`、页面接线、i18n、组件测试。

### M3 热力图（P1 🎨）

- **目标**：用时间 × 事件类型热力图展示登录事件分布，替代单维趋势图无法表达的维度。
- **优先级**：P1（backlog 2.4 明确项；与事件视图互补）。
- **范围**：热力图聚合接口（≤7 天按小时、≤30 天按天）、纯展示组件、桌面 / 平板 / 移动与浅 / 暗色基线。
- **验收标准**：矩阵行列与事件类型枚举一致；时间桶边界正确；无数据 / 加载 / 错误态；无横向溢出；颜色 token 可读；视觉基线通过。
- **不做什么**：不做 30 天以上窗口；不做前端二次聚合；不做下钻弹窗。
- **依赖**：M1、M2.1（筛选条件复用）。
- **交付物**：聚合端点、组件、视觉 spec 与基线；2–3 次提交。
- **风险与缓解**：大窗口查询慢 → 限制窗口 + 聚合索引；颜色对比不足 → Admin token + 视觉抽检。

#### M3.1 聚合接口

- **目标**：`GET /api/admin/login-events/heatmap` 返回时间桶 × 事件类型的计数矩阵。
- **验收标准**：`days=7` 按小时、`days=30` 按天；桶标签与排序稳定；与查询筛选共用条件；非管理员 403；空桶补零；单测覆盖跨日 / 跨小时边界。
- **交付物**：端点、共享 schema、单测。
- **依赖**：M2.1。

#### M3.2 热力图组件与视觉

- **目标**：`components/admin/logs/login-event-heatmap.vue` 渲染矩阵，支持主题与可访问名称。
- **验收标准**：桌面 / 平板 / 移动与浅 / 暗色基线；无横向溢出；`aria-label` 描述行列含义；空 / 加载 / 错误态；颜色使用 Admin token。
- **交付物**：组件、i18n、视觉 spec 与 6 张基线。
- **依赖**：M3.1。

### M4 可信设备与会话治理（P0 🛠️🛡️）

- **目标**：让用户与管理员看见并吊销可信设备，补齐按用户批量撤销会话与多方言脚本。
- **优先级**：P0（阶段 11 的可靠审计与 D14 会话边界需要可操作面；撤销脚本是迁入项）。
- **范围**：`TrustedDevice` 实体与采集、用户安全页列表 / 吊销、管理员用户详情列表 / 吊销、按用户批量撤销会话、多方言脚本、审计。
- **验收标准**：2FA 信任设备成功后出现记录；解析失败不影响验证并可回退只读列表；吊销同时删除 `verification` 行与实体；管理员 / 本人权限正确；批量撤销有二次确认与审计；脚本默认 dry-run。
- **不做什么**：不重置 2FA / 备份码（D4）；不代设密码（D8）；不做设备指纹 / 风险评分；不做 passkey。
- **依赖**：阶段 11 2FA 验证钩子、admin 插件会话能力。
- **交付物**：实体 + 端点 + UI + 脚本 + 测试；3–4 次提交。
- **风险与缓解**：`trust_device` cookie 非公开契约 → 契约测试 + 回退；批量误删 → dry-run + 二次确认 + 审计；权限越界 → `checkAdmin` / 本人校验。

#### M4.1 可信设备实体与采集

- **目标**：新增 `TrustedDevice` 表，并在 2FA 验证勾选信任设备成功时采集 identifier / UA / IP / 过期时间。
- **验收标准**：仅成功验证写记录；同一 identifier 去重并更新 `lastUsedAt`；失败 / 未勾选不写；解析 `trust_device` cookie 失败只 warn 并回退；审计 `trustedDevice.create`；实体与采集单测。
- **交付物**：实体、`server/utils/trusted-devices.ts`、2FA 验证钩子接线、建表脚本、单测。
- **依赖**：阶段 11 `two-factor-coverage` 插件；M1.1 建表约定。

#### M4.2 用户安全页

- **目标**：安全页展示当前用户的可信设备（设备 UA 摘要、IP、创建 / 过期 / 最近使用）并支持吊销。
- **验收标准**：`GET /api/security/trusted-devices` 只返回本人；`DELETE` 删除 `verification` 行 + 实体并审计；吊销当前设备时清除 `trust_device` cookie；空态 / 加载 / 错误态；5 语文案；视觉基线。
- **交付物**：2 个端点、`components/security/trusted-devices-panel.vue`、安全页接线、i18n、单测 / 视觉。
- **依赖**：M4.1。

#### M4.3 管理端与撤销脚本

- **目标**：管理员可在用户详情查看 / 吊销可信设备与全部会话；提供多方言撤销脚本。
- **验收标准**：管理员端点 `checkAdmin`；按用户批量撤销会话需二次确认并审计；可信设备吊销与用户侧同语义；脚本 `--dry-run` 默认、`--confirm` 执行，SQLite / MySQL / PostgreSQL 方言可用；执行前打印目标数量；文档注明 D14 既有会话不回溯。
- **交付物**：管理端端点、用户详情对话框接线、`scripts/security/revoke-two-factor-sessions.mjs`、测试、文档。
- **依赖**：M4.1、M4.2。
