### M1 登录事件 IP 索引

- **目标**: 让 IP 精确筛选与时间窗组合可走索引，消除大时间窗全表扫描。
- **优先级**: P1（性能与运维基础）。
- **范围**: `LoginEvent.ip` 列类型、复合索引、三方言 DDL 与部署指引；查询层口径。
- **验收标准**: 实体与三方言 `create.sql` 均为 `varchar(45)` 且存在 `(ip, created_at)` 索引；`database.md` 给出 ALTER 顺序与回滚；IP 筛选行为与响应字段不变，不新增隐式时间窗。
- **不做什么**: 不改 IP 解析与信任代理逻辑；不新增筛选字段。
- **依赖**: 无。
- **交付物**: 实体 / DDL / 文档 / 单测。
- **风险与缓解**: 既有库需 ALTER；先改类型再建索引并提供回滚语句。

#### M1.1 列类型与复合索引

- **目标**: `login_event.ip` 改为 `varchar(45)` 并补 `(ip, created_at)` 复合索引。
- **验收标准**: 实体与 SQLite / MySQL / PostgreSQL `create.sql` 同步；`database.md` 含 ALTER 语句；新装与升级路径均可用。
- **交付物**: `server/entities/login-event.ts`、三方言 `create.sql`、`docs/design/database.md`、`tests/unit/server/login-events-entity.spec.ts`。
- **依赖**: 无。

#### M1.2 IP 筛选与索引口径

- **目标**: 固定 IP-only 查询由 `(ip, created_at)` 复合索引覆盖，不引入隐式时间窗。
- **验收标准**: 查询构造器在有 IP 条件时不追加默认时间窗（有 `start` / `end` 时才使用）；单测锁定谓词与响应字段不变；文档写明大时间跨度建议显式带时间窗及原因。
- **交付物**: 查询 schema / 仓储过滤、单测、`server/api/admin/login-events/index.get.ts` 注释、`security-observability.md` 口径。
- **依赖**: M1.1。

### M2 统计与热力图方言聚合

- **目标**: 把窗口内分桶从 JS 全量载入改为数据库侧聚合，内存与传输只随桶数增长。
- **优先级**: P1（可观测性规模化）。
- **范围**: `getLoginEventStats` 的 `dailyTrend`、`getLoginEventHeatmap` 的分桶与行聚合。
- **验收标准**: 两种查询均使用方言 SQL `GROUP BY`；JS 只补零桶与排序；响应字段、UTC 时区与窗口上限不变；三方言 SQL 契约测试通过。
- **不做什么**: 不改接口路径、响应结构、前端组件与保留期逻辑。
- **依赖**: M1。
- **交付物**: 仓储聚合、方言辅助、单测、契约断言。
- **风险与缓解**: 分桶表达式随方言差异漂移；按方言断言标签并保留 JS 补零。

#### M2.1 趋势统计方言聚合

- **目标**: `dailyTrend` 改为按 UTC 天在数据库侧 `GROUP BY`。
- **验收标准**: SQLite / MySQL / PostgreSQL 均返回 `YYYY-MM-DD` 桶；空窗口返回空数组（补零只适用于热力图固定桶轴，保持阶段 12 响应语义）；单测锁定 `timezone: 'UTC'`。
- **交付物**: `server/utils/login-events/repository.ts`、方言 SQL 辅助、单测。
- **依赖**: M1.1。

#### M2.2 热力图方言聚合

- **目标**: 热力图的 `type × bucket` 计数在数据库侧完成。
- **验收标准**: 7 天按小时、30 天按天；桶标签与现状一致；空桶为 0；单测覆盖两种粒度。
- **交付物**: 仓储聚合、单测。
- **依赖**: M1.1。

#### M2.3 三方言契约与性能回归

- **目标**: 固化方言 SQL 契约并验证窗口上限行为。
- **验收标准**: 单测按方言断言谓词 / 占位符 / 分桶函数；统计与热力图仓储不再调用 `repository.find` 拉取窗口事件（mock 断言）且生成 SQL 含 `GROUP BY`；文档记录聚合口径。
- **交付物**: 契约测试、`security-observability.md` 性能说明。
- **依赖**: M2.1、M2.2。

### M3 运维脚本与发布门禁

- **目标**: 补齐多方言手动清理入口、让重建路径经过安全门禁、收敛 medium 依赖告警。
- **优先级**: P1（运维与发布安全）。
- **范围**: `prune-login-events.mjs`、`docker-publish.yml`、依赖 override / 升级评估。
- **验收标准**: 清理脚本三方言可用且默认 dry-run；`mode=build` 执行门禁、`retag` 不重复扫描；3 条依赖告警各自有升级或延期结论并写入 backlog。
- **不做什么**: 不改保留期默认值；不给 `retag` 增加重复扫描；不盲升大版本依赖。
- **依赖**: 无。
- **交付物**: 脚本、工作流、lockfile 或 backlog 记录、测试。
- **风险与缓解**: 大版本依赖破坏工具链；逐包升级并跑完整门禁，失败即回退。

#### M3.1 多方言清理脚本

- **目标**: `prune-login-events.mjs` 支持 SQLite / MySQL / PostgreSQL。
- **验收标准**: 方言客户端 + 参数化 DELETE；默认 dry-run、`--confirm` 执行；`--days` 参数化；单测覆盖三方言 SQL 与 SQLite 实际删除。
- **交付物**: 脚本、单测、部署文档指引。
- **依赖**: 无。

#### M3.2 docker-publish 重建门禁

- **目标**: `mode=build` 构建前执行安全告警门禁。
- **验收标准**: 工作流在 build 前调用 `check-alerts.mjs`，使用正确的 Dependabot / Code Scanning token；`retag` 不触发；失败即阻断。
- **交付物**: `.github/workflows/docker-publish.yml`。
- **依赖**: 无。

#### M3.3 依赖告警收敛

- **目标**: 3 条 medium 告警各自闭环或写明延期条件。
- **验收标准**: `glob` 升级到 ≥14.0.2（override 或直接升级）；`minimatch` / `@nuxt/schema` 经门禁验证后升级，不兼容则记录触发条件；`pnpm audit` 结果与 backlog 同步。
- **交付物**: `package.json` / `pnpm-lock.yaml` 或 backlog 记录。
- **依赖**: 无（可与 M2 并行）。
