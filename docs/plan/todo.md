### M1 验证码插件注册与配置口径

- **目标**: 验证码插件只在服务端配置可用时挂载，部分配置按「未启用」处理并留下可操作告警。
- **优先级**: P1（安全与可用性，当前会以 500 暴露）。
- **范围**: `lib/auth.ts`、`server/utils/captcha-config.ts`、`utils/web/captcha.ts`（只读口径）、相关单测。
- **验收标准**: provider 或 secret 任一缺失时不挂载插件且请求不 500；provider + secret 齐全时按既有 endpoints 挂载；部分配置在启动 / 首次求值时 warn 一次并写明缺哪一项。
- **不做什么**: 不改前端 `isCaptchaEnabled()` 的同步契约、不改 endpoint 列表、不改验证码 UI。
- **依赖**: 无。
- **交付物**: 注册条件改动、配置矩阵单测、告警文案。
- **风险与缓解**: 告警刷屏 → 每进程只 warn 一次；挂载判定变化影响既有登录 / 注册测试 → 同批跑全量单测。

#### M1.1 注册条件改按配置可用性

- **目标**: `lib/auth.ts` 用 `getCaptchaConfig()` 的结果决定是否挂载，去掉非空断言。
- **验收标准**: 配置返回 `null` 时插件不在 `plugins` 中；配置非空时挂载且参数与 `getCaptchaConfig()` 相等。
- **交付物**: `lib/auth.ts` 改动、注册条件单测。
- **依赖**: 无。

#### M1.2 配置矩阵与不一致告警

- **目标**: 四种配置组合（仅 provider / 仅 siteKey / 仅 secret / 齐备）行为与告警可回归。
- **验收标准**: 组合矩阵单测通过；部分配置 warn 文案点名缺失项；前端判定与后端判定的差异写入口径注释。
- **交付物**: 单测、告警实现、口径注释。
- **依赖**: M1.1。

### M2 自定义端点服务端验证码校验

- **目标**: `change-email` 与 `two-factor/send-otp` 的 `x-captcha-response` 由服务端校验。
- **优先级**: P1（安全，当前只有前端门禁）。
- **范围**: 新增 `server/utils/captcha-verify.ts`、两个端点、`i18n/locales/*/errors.json`、单测。
- **验收标准**: 启用验证码时缺 token 返回 400 `CAPTCHA_REQUIRED`、token 无效返回 400 `CAPTCHA_INVALID`、provider 不可用返回 503 `CAPTCHA_UNAVAILABLE`；未启用验证码时行为与现状一致；错误消息走 i18n。
- **不做什么**: 不改前端发送逻辑、不给其他端点（登录 / 注册）改校验路径（由插件负责）。
- **依赖**: M1（是否启用需单一判定）。
- **交付物**: 校验工具、端点接入、错误码与 5 语言键、单测。
- **风险与缓解**: provider 超时导致发送不可用 → 明确 503 与日志；测试依赖网络 → 全部走 mock fetch。

#### M2.1 统一服务端校验工具

- **目标**: 三种 provider 的 `siteverify` 调用、超时与结果归一化收敛到一个工具。
- **验收标准**: recaptcha 额外校验 `minScore`；turnstile / hcaptcha 只校验 `success`；网络异常与超时抛出可识别错误；未启用时返回「跳过」。
- **交付物**: `server/utils/captcha-verify.ts` 与单测。
- **依赖**: M1.1。

#### M2.2 修改邮箱端点接入

- **目标**: `/api/security/change-email` 在启用验证码时校验 token。
- **验收标准**: 三种错误码分支与成功分支各有断言；未启用时不读取该头。
- **交付物**: 端点改动、单测。
- **依赖**: M2.1。

#### M2.3 2FA 发送验证码端点接入

- **目标**: `/api/security/two-factor/send-otp` 在启用验证码时校验 token。
- **验收标准**: 与 M2.2 同一口径；校验失败时不调用上游 `sendTwoFactorOTP`、不产生投递记录。
- **交付物**: 端点改动、单测。
- **依赖**: M2.1。

### M3 登录事件来源 IP 契约

- **目标**: 来源 IP 归一化后写库，三种方言与 45 长度列不再出现写入分叉。
- **优先级**: P2（线上数据完整性）。
- **范围**: 新增 `server/utils/client-ip.ts`、`server/utils/audit-log.ts`、登录事件插件路径、单测。
- **验收标准**: XFF 首段、`[IPv6]`、`1.2.3.4:5678`、`fe80::1%eth0`、多值 XFF、非法值、>45 字符各有断言；非法 / 超长回落 `null`；合法 IPv4 / IPv6 原样保留。
- **不做什么**: 不引入 `trust proxy` 配置开关、不改数据库列类型、不改登录事件的统计与展示口径。
- **依赖**: 无。
- **交付物**: 归一化工具、写入路径接入、单测。
- **风险与缓解**: 既有审计断言依赖原值 → 先补边界用例锁定新口径，再改写入路径；`requestAuditMeta` / `eventAuditMeta` 共用工具避免双口径。

#### M3.1 IP 归一化工具

- **目标**: 单点实现 `normalizeClientIp(raw)`，覆盖方括号 / 端口 / zone index / 非法值。
- **验收标准**: 边界矩阵单测通过；函数纯函数、无 IO。
- **交付物**: `server/utils/client-ip.ts` 与单测。
- **依赖**: 无。

#### M3.2 写入路径接入

- **目标**: 审计日志与登录事件的来源 IP 都走归一化。
- **验收标准**: `requestAuditMeta` 与 `eventAuditMeta` 返回归一化结果；登录事件插件写入的 `ip` 与之一致；失败不阻断认证。
- **交付物**: `audit-log.ts` 改动、插件路径断言。
- **依赖**: M3.1。

#### M3.3 三方言与长度契约断言

- **目标**: 45 长度列在三方言下不再因超长 / 带端口值失败。
- **验收标准**: 超长 / 带端口 / 非法值写入结果为 `null` 或合法 IP；仓储层断言通过；既有登录事件测试不回归。
- **交付物**: 仓储层单测、回归断言。
- **依赖**: M3.2。
