## 4. 上游问题与项目侧边界

`CaomeiButton` 的根节点在 1.4.0 会因内建提示包装层（`CaomeiPassthrough` / `CaomeiTooltip`）截断父组件 scoped id。这是**库级兼容性缺口**，不是本项目独有：

- 所有「在 `CaomeiButton` 根类上写 scoped 样式」的用法都会失效，且 Vue 不会给出警告。
- 项目侧目前用 wrapper + `:deep()` 规避；若上游恢复「未启用提示时根节点即 `<button>`」，可删除这些规避（见 [backlog 候选](../../plan/backlog.md#34-ui-与主题)）。
- 同批的 `display` / `border` `!important` 与长语言 `white-space` 覆盖也建议在上游修复后复核是否仍需要。

## 6. 后续边界

- 本批不改变阶段 12 的范围与执行顺序；阶段 12 仍从 M1.1 开工。
- 1.4.0 新增的 `Cascader` / `TimePicker` / `InputOtp` / `Rating` / `Timeline` / `Transfer` / `Empty` / `Result` 等组件未在本项目使用，不做批量替换。
- `CaomeiButton` 的上游 issue 需在提报前查重；提报内容以 §4 的最小复现（父组件 scoped 类 + 1.4.0 按钮）为准。
- 社交按钮覆盖仍有 `background-color` / `border-radius` / `font-size` 等声明与库 token 同值，当前“零差异”无法区分“覆盖生效”与“token 恰好等值”；下次升级前应按库文档化钩子收敛（backlog 3.4）。
- ja / ko 长语言的 register / forgot-password / sso-login 未纳入视觉矩阵，当前只有 login 有 localized-core 基线；补测与复核条件见 backlog 3.4。
- `login` / `register` / `forgot-password` / `change-password` 中与全局 `.btn` / `.btn-primary` 完全等值的 scoped 死规则建议随下一次触及这些文件的提交删除，避免误判为仍生效。
