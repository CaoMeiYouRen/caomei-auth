# 2026-11-27 阶段 16 范围登记：平板收尾与 Admin 移动端可访问性

> **状态**：2026-11-27 登记，2026-11-28 收口（见 [阶段 16 收口记录](./2026-11-27-phase16-closure.md)）。用户 2026-11-27 在「A 安全与配置正确性 / B 平板与移动端残余 / C 质量基建 / D 邮件链接重置」中选择 **B**；D52–D58 为拟定口径，确认开工时生效。如用户改判，同批更新本文件、[todo.md](../../plan/todo.md)、[roadmap.md](../../plan/roadmap.md) 与受影响规范。
> **依据**：[阶段 15 收口记录](./2026-11-27-phase15-closure.md)、[backlog §3.2 / §3.4 / §3.5](../../plan/backlog.md)、[移动端认证审计](./2026-11-25-mobile-auth-audit.md)、2026-11-27 用户范围决策（B）。
> **规划模型**：5 大条目 / 10 小条目（[规划规范](../../standards/planning.md) §4）；小条目 10 条，达到建议下限；不上收 Admin 数据表卡片化（D49 延后，另立候选）。

## 1. 目标

- 把阶段 15 只在 ≤768 生效的登录 Tab 与右侧安全廊道扩到 ≤1024，覆盖 769–1024 平板 / 横屏带，消除该区间的悬浮按钮遮挡与 Tab 横向滚动。
- 为 1024 横向补轻量视觉基线，锁住平板断点的像素回归。
- 给 `/sso-login` 接入暗色主题，消除「内容浅色 + 页脚暗色」的割裂。
- 收敛 Admin 移动端导航的可访问性与首帧体验：收起态链接有可访问名称、SSR 首帧不跳变、参考态漂移有登记、就绪判定重新收敛到内容区。

## 6. 执行顺序

M1 → M2 → M3 → M4 → M5。

先收平板断点并补 1024 基线，再做 SSO 暗色，随后处理 Admin 可访问性与首帧，最后统一门禁与归档。M2 依赖 M1 布局稳定；M3 的基线独立采集。

## 7. 不做什么

- 不做 Admin 数据表卡片化与侧栏重设计。
- 不做 SSO 页面视觉改版（只接暗色 token）。
- 不做 769–1024 之外的新断点，不新增语言。
- 不改认证流程、鉴权语义与 API 契约。
- 不做 Demo 模式角标偏移专项。

## 8. 风险与缓解

| 风险 | 缓解 |
| :--- | :--- |
| 廊道扩到 1024 使 769–1024 卡片内容再收 4rem，长语言换行增多 | 只对登录 / 注册 / SSO 三页生效；1024 基线逐张归因，桌面 >1024 不变 |
| 1024 矩阵拉长 CI | 只采 4 张浅色；复用既有视口配置 |
| SSO 暗色 token 映射错误 | 先对比 `theme.scss` / `dark-mode.scss` 的既有 token，再逐块替换；暗色基线 2 张 + 计算样式断言 |
| CSS-first 收起改动侧栏结构 | 只替换 v-show 的显示控制与初始状态，导航信息与顺序不变；admin 12 张基线重采并归因 |
| 参考态 parity 被误判为新回归 | D57 豁免与测试规范留痕，parity 审计按登记清单排除 |
