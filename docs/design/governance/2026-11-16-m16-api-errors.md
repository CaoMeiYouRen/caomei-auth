## 2. 实现要点

- **统一判定**：`isLocalizedApiPath` 只保留 `/api` 根前缀（归一化后比较），因此 `/api/admin/**`、`/api/file/**`、`/api/social/**` 都会返回 `Content-Language` 与 `Vary: Accept-Language, Cookie`。
- **错误键映射**：管理端 404 / 409 / 400 用 `createLocalizedError(event, { statusCode, key })`；校验失败用 `resolveValidationMessage(issue.message, t)`，无 `t` 时回退 `errors.admin.paramsInvalid`，不再拼中文。
- **500 口径**：只返回 `errors.server.internal`（管理端）或 `errors.admin.*Failed`，底层 `error.message` 仅进日志，避免把内部错误或中文堆栈透给客户端。
- **成功消息**：`{ status, success, message }` 结构的响应同样按语言输出（创建 / 更新 / 删除 / 启用禁用 / 角色同步），前端 Toast 直接展示。
- **社交登录展示名**：`allProviders` 仍是内置元数据，新增 `localizeProvider` 在响应时按 `auth.social.*` 覆盖匿名 / 微信 / QQ / 抖音 / 微博的名称、按钮与 tooltip；品牌名（GitHub / Google 等）保持原样。
- **静态守卫**：新增单测扫描 `server/api/**` 与 `server/middleware/**`，一旦在 `createError` 对象或 `message:` 字面量里重新写入中文即失败；管理端按文件要求接入服务端翻译，避免新增 handler 漏接。

## 4. 已知边界

- `statusMessage` 仍由 h3 默认值填充（未显式设置时由 `STATUS_CODES` 补，4xx 为 `Not Found` 等），客户端展示以 `message` 为准。
- 上传每日限额改用 429 + 本地化 `message`；前端 `user-avatar` 的 `useFetch` 只读技术错误串，Toast 仍回退 `profile.avatar.uploadFailed`（已本地化），body 文案主要供 API 消费者与日志使用。
- `composables/admin/*` 的 `errorMessage()` 只读 `error.message`，fetch 层 500 的技术串不含 body `message`；管理端 500 键当前对 Toast 不可见（改动前同样如此），已登记 backlog「Admin API 错误文案的读取链路」。
- Admin OAuth 应用的删除 / 启停仍以 body `status` 表达失败、HTTP 为 200，前端不校验 `success` 时仍会弹成功 Toast；已登记 backlog「Admin OAuth 应用接口返回 HTTP 200 + body status」。
- Admin 侧校验失败对非 `validation.*` 文案原样返回，类型级错误会透出 Zod 默认英文；已登记 backlog「Admin 校验错误统一 Zod error map」，M17 统一接 `createZodErrorMap`。
- `server/api/admin/logs/sessions.get.ts` 的 `location: '未知'` 是响应数据字段（当前 UI 不渲染），未纳入本地化。
- 社交登录的内置元数据仍保留中文初值作为兜底，HTTP 响应统一被 `auth.social.*` 覆盖。
- `errors.admin.*` 放在 `errors` 模块而非 `server-only`：这些键体量小且与既有 `errors.*` 同域，拆模块会让 `createLocalizedError` 需要二次装配；`server-only` 仍保留给后续纯服务端长文案。
- 静态守卫覆盖对象字面量写法；`createError('中文')` 字符串重载、常量间接与正则字面量仍未覆盖，后续可用 AST 收紧。
- Demo 守卫的中文标签只在静态守卫层面保证，暂无「en 下 `data.message` 为英文」的行为用例。
- Admin 的 `en-US` 视觉基线在 M17 统一补。
