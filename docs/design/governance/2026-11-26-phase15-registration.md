# 2026-11-26 阶段 15 范围登记：认证移动端可用性

> **状态**：2026-11-26 登记，2026-11-26 用户确认开工（进行中）。§2 的 D45–D51 为拟定口径，随登记生效；如用户改判，开工前同批更新本文件、[todo.md](../../plan/todo.md)、[roadmap.md](../../plan/roadmap.md) 与受影响规范。
> **依据**：[移动端认证审计](./2026-11-25-mobile-auth-audit.md)（2026-11-25，390×844 / 360×640，5 语言 × 19 页）、[backlog §3.5](../../plan/backlog.md#35-移动端与认证可用性)、[阶段 14 收口记录](./2026-11-26-phase14-closure.md)、用户 2026-11-26 范围决策（A + Admin 基础可用）。
> **规划模型**：5 大条目 / 12 小条目（[规划规范](../../standards/planning.md) §4 / §7 / §8）；小条目 12 条，低于 15 条上限；不再合并的原因是登录 Tab、code-row、SSO 安全区与悬浮控件的修复点与验收互不重叠，合并会放大单条风险。

## 1. 目标

- 让 5 个启用语言的认证首屏在 390 / 360 下可用：登录方式完整可见、验证码行不溢出、SSO 标题不被遮挡。
- 消除固定悬浮按钮对登录 / 注册 / SSO 页可交互控件的遮挡，并补可回归的相交断言。
- 收敛个人中心与 Admin 后台的移动端基础可用性：操作行换行、侧栏默认收起、输入字号 ≥16px；不做 Admin 数据表卡片化。
- 让 OAuth 授权入口跟随用户已选语言，并为移动端会话卡片补跨语言像素保护。
- 建立 5 语言 390 / 360 的轻量视觉矩阵，作为上述修复的回归保护。

## 6. 执行顺序

M1 → M2 → M3 → M4 → M5。

先修首屏与遮挡（M1 / M2），再收敛个人中心与 Admin（M3），随后做 OAuth 入口语言与跨语言基线（M4），最后统一 5 语言矩阵与收口（M5）。M4 的基线依赖 M1–M3 的布局稳定后采集。

## 7. 不做什么

- 不改认证流程、鉴权语义与 API 契约。
- 不做 Admin 数据表卡片化与侧栏重设计。
- 不做 OAuth web 客户端 http 回环联调支持（留在 backlog）。
- 不做 `/sso-login` 暗色主题（留在 backlog §3.4）。
- 不新增语言、不改 i18n 启用集合与 SEO 策略。
- 不做悬浮按钮体系重构（仅安全区与位置避让）。

## 8. 风险与缓解

| 风险 | 缓解 |
| :--- | :--- |
| 登录 Tab 换行导致高度变化，触及既有移动端基线 | 只改登录页窄屏，按受影响的 login 基线逐张归因后重采 |
| 安全区 padding 改变认证页滚动高度 | 用页面级重叠面积断言替代整页位置断言，固定时钟与文案 |
| code-row 改动影响 2FA / 换邮箱 | 复用同一容器选择器，补 390 / 360 组件级断言 |
| OAuth 入口重定向引入循环 | 仅对无语言前缀的 `/login`、`/oauth/consent` 生效，保留原有 query / state，补未登录 / 已登录两种断言 |
| Admin 输入字号改变表格密度 | 只对移动端输入生效，桌面保持 14px；表格列宽与既有基线复核 |
| 5 语言矩阵拉长 CI | 新增上限 20 张，按 390 / 360 与失败风险选页，复用阶段 14 基线 |
