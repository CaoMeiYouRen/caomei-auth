## 3. DataTable 映射与 spike 结论

### 3.1 结论

**直接使用 `CaomeiDataTable`**。原因：

1. `columns` + `accessor`（含点号路径）+ `cell` 函数 / `#cell-{key}` 插槽已覆盖 Admin 现有 `<Column>` + `#body` 组合。
2. 受控 `selection` 回传**完整行对象**，与现有 `selectedUsers` 用法一致；强制 `rowKey` 后行对象稳定。
3. `lazy` 不切片 `data`，与 `BaseTable` 的懒加载分页一致；`page` 为 1 基，页面层保留 0 基并换算。
4. 排序事件直接为 `asc` / `desc`，只需把现有 `1 / -1` 在页面层换算。
5. 空态 `#empty`、加载态 `loading`、`aria-busy`、`aria-sort` 均可用。

不建薄封装：4 个页面的列定义、操作列、筛选条件差异大；共享封装会把 `columns` 与页面状态耦合，且 1.2.0 的 token 已覆盖密度与选择列宽度。

### 3.2 映射表（已由测试锁定）

| PrimeVue / `BaseTable` | `CaomeiDataTable` | 迁移处理 |
| :--- | :--- | :--- |
| `:value` | `:data` | 直接映射 |
| `:data-key` | `:row-key` | 必填 |
| `<Column field header sortable>` | `columns: [{ key, header, accessor, sortable }]` | `field` → `accessor`，`key` 用于插槽名 |
| `#body="{ data }"` | `#cell-{key}` / `cell` 函数 | 插槽优先 |
| `#header`（工具栏） | **无对应插槽** | 工具栏留在卡片外层 |
| `#empty` | `#empty` / `empty-text` | 直接映射 |
| `selection-mode="multiple"` | `selection-mode="multiple"` | 同义 |
| `v-model:selection` | `:selection` + `@update:selection` | 受控；选择存**行对象** |
| `:first`（0 基） | `:page`（1 基） | `page + 1`；`@page` 回写 `first / rows` |
| `:rows` / `:total-records` / `:lazy` | 同名 | 直接映射 |
| `:sort-field` / `:sort-order`（1/-1） | `:sort-field` / `sort-order`（`asc`/`desc`） | 页面层换算 |
| `@page` | `@page` / `@update:page` | 载荷含 `page` / `rows` / `first` / `pageCount` |
| `striped-rows` | `striped` | 同义 |
| `responsive-layout="scroll"` | 无 prop | 外层 `overflow-x: auto` |
| `paginator-template` / `current-page-report-template` | **无** | 登记为有意差异；总数保留在表格标题（现有页面已如此） |
| 首 / 末页按钮 | 默认 `showEdges=false` | 需要时显式开启；不默认改变现有分页形态 |

### 3.3 关键差异

- **分页器没有「x 到 y 共 n 条」报告**：测试 `lazy 模式不切片 data…` 明确断言分页器文本不含总数。页面标题必须继续展示总数（现有 4 个页面均已展示）。
- **选择列不是原生 checkbox**：`CaomeiCheckbox` 由 reka-ui 渲染为 `role="checkbox"` 的按钮；交互测试与 e2e 选择器需按 role 定位。
- **`page` 1 基、`first` 0 基**：`useDataTable` 的 0 基 `page` 不要直接传给 `CaomeiDataTable`。
- **受控排序**：必须同时提供 `sortField` / `sortOrder` 并回写，否则内建排序不生效。

## 4. Dialog / Select / DatePicker / Toast 映射

| 现有 | 目标 | 处理 |
| :--- | :--- | :--- |
| `BaseDialog`（`visible`、`width`、`breakpoints`） | `BaseDialogV2`（`open`、`size`） | 保留 V2 薄封装；`@update:open` → `@update:visible`；宽度按内容选 `sm/md/lg` |
| `#footer` + PrimeVue Button | `#footer` + `CaomeiButton` | 按钮文案走默认插槽（`label` 只映射 aria-label） |
| `InputText` | `BaseInputV2` / `CaomeiInput` | 保留 label / error / aria 组合 |
| `Select` / `Dropdown` | `CaomeiSelect` | `option-label` → `optionLabel`、`option-value` → `optionValue`、`show-clear` → `clearable`；窄容器给固定宽度（「CN +86」裁切问题） |
| `Textarea` / `Checkbox` / `Password` / `InputNumber` | `CaomeiTextarea` / `CaomeiCheckbox` / `BasePasswordV2` / `CaomeiInputNumber` | `v-model` 语义一致；Password 保留显隐按钮 a11y |
| `Badge` | `CaomeiTag` | tone / variant 映射；`value` → 默认插槽 |
| `Avatar` | `CaomeiAvatar` | 图片失败回退到 label |
| `Menu` | `CaomeiMenu` / DropdownMenu | 批量操作菜单 |
| `Accordion` | `CaomeiAccordion` | SSO 表单分组 |
| `useToast` / `useConfirm` | `caomei-ui` 同名 composable | 逐批切换，显式 import；API 见迁移评估 §7.3 / P3 记录 |

**DatePicker range（`/admin/logs`）**：

- 模型 `[Date, Date] | null`；只有两端都选中才发请求，避免中间态触发。
- 1.2.0 无 `showClear` / `manualInput`：在筛选区放独立「清除」按钮，把模型置 `null`。
- 时区 / 格式化继续用 `dayjs`，不改业务语义；range 不含时间（时间部分被忽略）。

### 5.2 立即修：PrimeVue 暗色变量从未生效

`nuxt.config.ts` 原配置 `darkModeSelector: 'html.dark'`。PrimeVue 只接受 **class / `system`** 形式的选择器；复合选择器会生成 `html.dark :root{…}`（后代选择器），`:root` 是 `<html>` 自身，因此暗色变量永远不匹配。证据：暗色页面的 `--p-select-background` 仍为 `#ffffff`，且组件主题样式表不含任何暗色规则。

修复：改为 `darkModeSelector: '.dark'`（应用只切换 `<html>` 的 `.dark` 类，语义等价），并补注释。影响：

- 暗色下 PrimeVue 组件（Select / DataTable / Paginator / Dialog）使用正确的暗色 token；浅色不变。
- 暗色主色由 `primary.500` 切到 `primary.400`（`#e63946` → `#ff6b6b`），属于暗色对比度修正，已重采自基线。
- 暴露并修复语言切换器：`--p-surface-0` 在暗色下仍是白色（PrimeVue 暗色 surface 是反向色阶），导致白底白字；改用语义 token `--p-content-background` / `--p-content-hover-background`。

### 5.3 立即修与随批次修

**立即修（P4-0，只因全局暗色基座暴露的不可读文本，不改布局 / 组件）**：

- `layouts/admin.vue`：布局、侧边栏、导航、页脚全部改用 `--admin-*`。
- `pages/admin/users.vue`（试点页）：容器、表头、行、分页器、文本、空态。
- `pages/admin/oauth/applications.vue`：容器、标题 / 说明、表头、行、`client-id` 徽标、空态。
- `pages/admin/sso/providers.vue`：页面底色、头部 / 筛选 / 列表容器、标题、表头 / 行、提供商信息、日期、空态。
- `pages/admin/logs.vue`：子组件表格的表头 / 行 / 分页器 token 兜底（避免白底白字）。

**随批次修（M4 / M6 / M9 / M10）**：

## 8. P4-1 任务单（Admin 用户页）

1. 页面状态继续使用 `useDataTable`（0 基 `page`、`sortField`、`sortOrder`、`selection`）。

3. 页面级筛选：`InputText` → `CaomeiInput` / `BaseInputV2`，`Select` → `CaomeiSelect`，刷新按钮 → `CaomeiButton`。
4. 页面容器 / 表头 / 行继续使用 `--admin-*` token，不再引入新的浅色硬编码。
5. 不迁移 4 个对话框（M3）；M2 提交时白名单不变。自基线随页面迁移同批重采（见[阶段 4 登记](./2026-11-10-phase4-registration.md) §3 修正说明）。
6. 验收：页面无 PrimeVue 模板标签 / 显式导入；分页 / 排序 / 选择 / 空态 / 加载态与参考态一致；`pnpm typecheck` / `pnpm test` / `pnpm test:visual` 通过。
