## 2. 版本核验与 lockfile 归因

**版本事实**（2026-11-15 registry 核验）：`caomei-ui@1.3.0` 可解析；peer 依赖与 1.2.0 一致（`vue ^3.5` / `echarts ^6` / `@nuxt/kit ^4` / `vue-echarts ^8` / `md-editor-v3 ^7.1`）；`PRE_REGISTERED_LOCALES` 仍为 `zh-CN` / `en-US`，`CaomeiConfigProvider` props（`locale` / `messages`）未变。

lockfile 逐条归因：

| 包 | 变更 | 归因 |
| :--- | :--- | :--- |
| `caomei-ui` | 1.2.0 → 1.3.0 | 本批目标 |
| `reka-ui` | 2.10.4 → 2.11.0 | caomei-ui 1.3.0 捆绑依赖升级 |
| `@floating-ui/vue` | 1.1.11 → 2.0.1 | reka-ui 2.11.0 依赖升级；移除 `vue-demi`，改为直接 peer `vue >=3.3` |
| `conventional-changelog-cmyr-config` | 3.0.0 → 3.1.2 | **无关漂移**：`pnpm add` 按 `^3.0.0` 重解析的 devDependency（新增 `handlebars` 依赖），不参与运行时与构建产物；随本批登记，未额外改动发布链路 |

`pnpm-workspace.yaml` 由 pnpm 自动把 exclude 写成 `caomei-ui@1.2.0 || 1.3.0`，已手工收紧为 `caomei-ui@1.3.0` 并更新注释。

## 3. 视觉回归与差异归因

首次 `pnpm test:visual`：**79 passed / 23 failed**，失败项全部落在 Admin 各页与 `profile`；登录 / 注册 / SSO / OAuth / 错误页零差异。其中 4 项（`admin-users` 弹窗基线）在升级前即已与 HEAD 代码不一致（见下表），这 4 项同时包含 1.3.0 的分页右移；其余 19 项由 1.3.0 的可见变化与遮罩矩形变化引起。

逐项归因（像素级差分 + 1.2.0 / 1.3.0 npm tarball 对照）：

| 差异 | 位置 | 判定 |
| :--- | :--- | :--- |
| 分页组整体右移 16px | Admin 全部数据页分页区（`Paginator`） | **上游预期**：1.3.0 把每页条数选择器默认宽度由 `6rem` 降为 `5rem`，并强制 Select 触发高度固定 32px；分页右对齐，故整组右移。页码 / 选择器 / aria 标签与交互均未变 |
| 暗色字段内部表面色 `#232325` → `#1e1e1e` | `profile` 与 Admin 暗色页的输入框内部（亮色不可见） | **上游预期**：1.3.0 给 `.caomei-input__control` 增加 `align-self: stretch`（命中区修复），原生控件盒高度 18px → 44px；禁用态控件盒底色 `#1e1e1e` 的覆盖面积随之扩大，外壳底色 `#27272a` 不变。亮色下两色相同，故仅暗色可见 |
| `profile` 遮蔽矩形 390×18 @(885,418) → 390×44 @(885,405) | `profile` 的 `data-visual-mask` 原生 `input` | **测试夹具变化**：遮蔽矩形随上一行的控件盒高度变化；非遮蔽像素差异亮色仅 207px（最大通道差 32，字形抗锯齿） |
| 底部语言切换器字形 1px 级差异 | Admin 页左下角 | 字形抗锯齿噪声（框体、间距与颜色 token 未变） |
| `admin-users` 弹窗角色列内容差异（4 张：create / ban / detail / sessions） | 弹窗遮罩下方的用户表角色列（`sessions` 实测 x844–897） | **旧基线陈旧，与本批升级无关**：该列在 HEAD 基线上与当前渲染不一致，而角色标签外观只取决于 `components/base/status-badge.vue`（自 `47b7c8c` 未改）、`CaomeiTag` 的 soft/neutral/danger 规则与 token（1.2.0 / 1.3.0 实测一致）与表格布局（未变）。首次回归的 23 项里，这 4 项在升级前重跑同样会红，本批重采使其与代码恢复一致 |

> 归因口径：对 23 张基线做 HEAD ↔ 工作表逐像素重算（拉取 1.2.0 / 1.3.0 tarball 对照 CSS 与 token），并按「遮蔽色像素」与「非遮蔽像素」分别统计；上表数字均为实测。
>
> 结论：无功能性回退（分页 / 文案 / 交互 / 表单行为一致，暗色表面色变化来自上游命中区修复，角色标签颜色已与 `status-badge` 的 `info → neutral` 映射对齐）；按阶段 5 §5.6「受影响视觉基线重采」更新自基线，并在本节保留归因。

## 6. 与后续条目的边界

- `Select` / `Paginator` / `DataTable` / `Toast` / `Confirm` 的 **`en-US` 视觉基线**按阶段 5 §5.6 只在 M17 为核心页补采，本批不扩大视觉矩阵。
- 视觉掩码目前挂在原生控件（`user-basic-info` 的 `data-visual-mask`）上，几何会随上游控件盒变化；M17 补双语基线时一并迁到稳定的外壳元素，减少后续基线噪声。
- 1.3.0 的 `data-motion` 动效轴保持默认（`minimal`），不启用 `expressive`；`CaomeiIcon` 图标注册表仅在组件库内部替换 `@lucide/vue` 直引，项目侧未新增图标覆盖。
- 新增映射注释已写明：新增语言若不在 `PRE_REGISTERED_LOCALES` 内，须在 provider 挂载前 `registerLocale()`。
