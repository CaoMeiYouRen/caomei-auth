# 规划规范 (Planning Standards)

本文档定义草梅 Auth 的规划载体、新需求准入与状态同步规则。项目级角色矩阵、冲突顺序与安全红线以 [AGENTS.md](../../AGENTS.md) 为唯一权威事实源；本文只负责“需求如何进入规划、如何实施、如何归档”。

## 1. 规划载体

| 载体 | 文件 | 职责 |
| :--- | :--- | :--- |
| 路线图 | [roadmap.md](../plan/roadmap.md) | 中长期方向与已授权阶段的里程碑；方向不等于启动授权，候选详情留在 backlog |
| 待办事项 | [todo.md](../plan/todo.md) | 当前已授权阶段的原子条目、验收状态与未完成项指针 |
| Backlog | [backlog.md](../plan/backlog.md) | 已评估候选池、候选阶段组合与已决策但尚未登记阶段的过渡态 |
| 已完成归档 | [completed-work.md](../archive/completed-work.md) | 已完成工作与阶段交付摘要的唯一去处 |

> 不再新增与上述四类职责重叠的规划文件。专项子规划（如 `zod-migration.md`）保留为对应候选的详情载体，由 backlog 引用；`refactor.md` 为历史重构归档，不参与新条目流转，新重构候选统一登记 backlog。

## 2. 流转

```text
新需求 → 评估 → backlog.md → 用户明确决策 → todo.md 当前阶段 → 实施 → completed-work.md
                                      ↓
                                 roadmap.md 阶段摘要
```

## 3. 准入规则

1. **Backlog 优先**：功能、重构、体验优化、集成、监控等新需求先评估并登记到 `backlog.md`，不得直接写入 `todo.md`。
2. **不自动升级**：未经用户明确授权，backlog 候选不得进入 `todo.md`；AI 不得推断某条应作为最高优先级并默认启动。
3. **不擅自规划下一阶段**：`roadmap.md` 中未授权方向与 backlog 候选不构成启动授权；下一阶段范围须经需求评估与用户决策后登记。
4. **插队例外**：以 [AGENTS.md §5.1.2](../../AGENTS.md#51-迭代中途发现事项处理规则) 为准，仅以下情形可直接进入当前阶段，并须在任务记录或提交说明中写明“为何插队”：
    - 阻塞当前交付；
    - 明确功能回归；
    - 高风险安全 / 合规问题；
    - 导致当前任务无法闭环的基础缺陷。
5. **范围降级同样须用户裁定**：已授权条目内的子能力不自动升降级；先取证（用量 / 影响面 / 快照日期），再交用户决策，决策后同步全部载体。
6. **决策落定须同步全部载体**：用户决策后，除登记者外须同步受影响的规范、设计文档、AI 资产（skills / agents）与 `.session/`；只改一处会让仓库并存两套口径。
7. **完成态不得预写**：`todo.md` 的完成态与 Review Gate 的绑定以 [AI 协作规范](./ai-collaboration.md) F 阶段为准；规划载体不得提前写入未落地的完成状态。

## 4. 条目与阶段

- **阶段编号只在授权启动时分配**：编号取“已有最大编号 + 1”，仅授予经用户明确授权启动的阶段；未授权工作不预留编号。
- 每个阶段聚焦 **3–6 条主线**；每条主线写明执行范围、非目标与最小验收标准。
- 原子条目对应一个可独立验收、可独立提交的逻辑变更。
- 单个原子条目建议不超过 **10 个文件 / 800 行新增**；生成物（如 `pnpm-lock.yaml`、构建产物）不计入，但须与触发变更同提交。
- 超阈值时必须拆分为多个条目；未拆分且无正当理由的改动，`@code-auditor` 有权 Reject。
- 条目编号按阶段内顺序（M1 / M2 ……）；重编号或拆分后须回扫 `todo.md`、`roadmap.md`、backlog 与 `.session/` 中的全部引用。

## 5. 状态同步

- **开发前**：对齐 `roadmap.md` 与 `todo.md`，确认条目已获授权。
- **开发后**：同步 `todo.md` 状态与验收结果；完成项在阶段收口时迁入 [已完成工作归档](../archive/completed-work.md)。
- **归档清理**：已完成 / 已归档条目不得在 `todo.md`、`backlog.md` 保留交付摘要、归档指针或“闭环整理”段；`todo.md` 只保留“当前阶段状态（可为无进行中阶段）+ 未完成项汇总”，`backlog.md` 只保留尚未进入阶段的候选。
- **`.session/` 同步**：发生阶段登记、阶段归档或阶段范围变更时，须在同批同步 `.session/current-task.yaml` 与 `.session/runtime-state.json` 的阶段态。`.session/` 为 git-ignored 任务态，不进提交物，但会决定下一次 session 的恢复起点。
- **Session 收尾**：按 `full-stack-master` 的 Session 协议更新任务态；`.session/wisdom.md` 活跃条目达到阈值时提醒蒸馏。

## 6. 审计

本规范由 `@code-auditor` 在 Review Gate 中检查，至少覆盖：

1. 新事项是否有明确落点（当前阶段 / backlog），是否越阶段容量私自扩容；
2. `todo.md` 是否只含已授权阶段条目，完成态是否与 RG 结论同批；
3. 归档后 `todo.md` / `backlog.md` 是否已清理完成项；
4. 决策落定后受影响载体与 `.session/` 是否已同步。

违规按 blocker / warning 分级。未经授权把候选升级为当前阶段，或预写未落地的完成态，按 blocker 处理。
